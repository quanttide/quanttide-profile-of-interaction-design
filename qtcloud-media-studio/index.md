# QtCloud Media Studio 理想的交互设计体验

## 一句话

打开就是写作现场：左边草稿、中间成文、右边预览，写完一键送进公众号。

## 理想的体验

### 打开时：直接进入工作现场

- 第一眼是草稿清单和正在写的文章，没有中间页、没有弹窗
- 在写哪篇一眼可辨（清单里高亮），上次没写完的点一下就回来

### 写作时：三栏一屏

- 草稿、编辑器、排版预览始终同屏——写什么、排什么、成什么样，不用来回切换
- 切去别的分区（图文、视频、设置）再回来，稿子原样还在

### 交付时：主行动唯一

- 「复制到公众号」在编辑器上方的详情工具带里，一眼可辨，点了就有回执
- 配好服务端后旁边多一个「推到公众号」（次要样式）——没配连接就不给用户第二个按钮
- 未来的编辑工具（主题、字号、导出）也住这条工具带——它收所有对「当前这篇」的动作

### 管理时：各归其位

- 草稿的增、选、改发生在草稿清单里（点项打开、＋存为新草稿、保存写回），页面上不摆一排草稿按钮
- 设置沉在导航栏底部，与内容分区（文章/图文/视频）明确分开
- 未来分区（图文、视频）预留占位，位置从现在就定下

## 体验原则（这个应用的）

1. **列表–详情三栏**：导航栏 → 列表面板 → 详情区；列表面板与导航栏等高通栏，详情区无顶栏、通高直达窗口底
2. **归属原则：动作作用于谁，就住哪一栏**——动「当前这篇」的进详情工具带，动「草稿集合」的进清单（＋、保存），动「应用」的进导航栏
3. **工具带要安静、主行动唯一**：详情工具带是工具带不是标题栏——背景浅一档、按钮次要起步，只有交付动作是主按钮
4. **设置与内容分区分离**：设置入口放导航栏底部，不占分区位
5. **预留先于开发**：未来分区先占位声明结构，不等做完才出现
